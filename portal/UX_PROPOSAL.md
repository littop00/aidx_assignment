# BOM 포탈 UI/UX 분석 및 개선 제안 (구현 전 정리)

작성일 2026-08-31. 구현은 다음 세션에 진행.

## 제약사항 (필수)

- **BOM 관리 화면의 table 형태(레이아웃 구조)는 변경 금지** — 고객 요청사항.
  - 즉: 행/열 구조, 테이블 vs 카드/트리뷰 같은 구조적 변경 불가.
  - 셀 내부 시각효과(테두리 색, 배지, 하이라이트 애니메이션) 추가는 "형태 변경"이 아니므로 허용 범위로 간주.
  - 아래 제안 중 그룹 시각화(#7)는 테이블 구조를 유지한 채 셀/배지 스타일만 보강하는 방향으로 한정.

## 현재 버전 장점

- 보라 accent(#6C5CE7) + 카드형 레이아웃, Bootstrap 5 기반. 그림자(`--shadow-soft`) 통일감 있음.
- 토스트 알림(`#toast-slot`, 우상단 고정, 3초 페이드) 구조 이미 있음 — 재사용 쉬움.
- 그리드 sticky header, 국가별 컬럼 그룹 배경색 구분(`.country-group-header`) — 데이터 밀도 높아도 구획됨.
- 레벨 들여쓰기(`.level-indent`), 그룹 배지(`.group-badge`) — 계층 구조 최소 표현.
- htmx 부분 갱신(그리드 페이지네이션/필터) — 풀 리로드 없음.
- 진행률 바(`progress-block`), KPI 카드 — 대시보드 한눈에 상태 파악 가능.

## 현재 버전 단점

1. **입력 밀도 과부하** — `.bom-table input` 셀 수십 개 한 화면. 어떤 셀을 방금 수정했는지 구분 안 됨 (row 단위 `data-dirty`만 있고 cell 단위 시각 표시 없음).
2. **저장 상태 불투명** — 자동저장/임시저장/제출 3단계 개념이 사용자에게 명시적으로 안 보임.
3. **토스트가 마지막 메시지로 덮어써짐** — `slot.innerHTML =` 방식이라 에러 여러 개 발생해도 하나만 보임. 원인 셀로 이동 불가.
4. **접근성 취약** — 아이콘 전용 버튼(`bi-bell`, `bi-person-circle`) aria-label 없음. `--portal-muted: #9291A5` 명도 대비 낮음.
5. **모바일/좁은 화면 미지원** — 사이드바 고정 250px, 필터 4열 grid, 반응형 없음.
6. **동시 편집 충돌 감지 없음** — 여러 사용자가 동시에 그룹/담당 조작 시 조용히 덮어써질 수 있음.
7. **되돌리기(undo) 없음** — 그룹 지정/해제, 일괄 적용 모두 즉시 반영.
8. **관리자 대시보드 정보 과밀** — BOM 목록/국가설정/사용자관리/제출검토가 한 화면(`admin-grid` 2열)에 몰려 있음.
9. **다크모드/개인화 없음**.

## 개선 제안 (우선순위 순, 테이블 구조 유지 전제)

1. **셀 단위 저장 상태 시각화** — 수정된 셀 테두리 노랑 → 저장 성공 시 초록 깜빡임 후 회색 복귀 → 실패 시 빨강 유지 + hover 시 에러 메시지. `dirty` 추적을 row 단위에서 cell(`input`) 단위로 변경.
2. **토스트 스택화** — `innerHTML=` 덮어쓰기 → append. 에러 토스트는 자동 소멸 안 하고 X로 닫게, 성공만 자동 페이드.
3. **저장 상태 배지 상시 노출** — 헤더 근처 "마지막 저장: 방금 전" 텍스트 표시.
4. **행 강조 네비게이션** — 검증 실패 토스트 클릭 시 해당 행 스크롤+하이라이트.
5. **관리자 대시보드 탭 분리** — BOM 관리 / 사용자 관리 / 제출 검토 별도 탭 또는 서브메뉴로 분리 (이 화면은 BOM table이 아니므로 제약사항 무관).
6. **접근성 보강** — 아이콘 버튼 aria-label 전부 추가, muted 색상 대비 4.5:1 이상으로 조정.
7. **그룹 관계 시각화 보강 (테이블 구조 유지)** — 현재 텍스트 배지 유지하되, 들여쓰기 선(`.level-indent`) 영역에 세로 연결선만 CSS로 추가해 상위-하위 시각 연결 강화. 행/열 구조는 그대로.
8. **반응형** — 우선순위 낮음. 실사용자 전부 사내 PC인지 확인 필요 (미확인 시 보류).

## 확인 필요 (다음 세션 시작 시 질문)

- 동시 접속/동시 편집 상황 실제로 자주 있는지 (락/충돌 감지 필요성 판단).
- 모바일/태블릿 사용 여부, 아니면 전부 사내 PC인지.
- 위 항목 중 다음 세션에서 어디부터 구현할지 (전체 or 일부 우선).
