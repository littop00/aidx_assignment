# 재료비 관리 포탈 - Work Flow (Admin / User)

실제 라우트/로직 기준으로 작성함. 케이스별로 정상 흐름 + 예외 흐름 포함.

---

## 공통

- 로그인: `/login` (username/password). 실패 시 재입력.
- 로그아웃: 우측 상단 로그아웃 버튼.
- 환율 위젯(USD/EUR): 상단바 상시 표시. "환율 갱신" 버튼으로 즉시 갱신 (admin/user 공통).
- "엑셀 다운로드": 현재 BOM 전체를 템플릿 양식으로 다운로드 (admin/user 공통).

---

## Admin Work Flow

### 케이스 A-1. 신규 BOM 배포 (최초)
1. `BOM 관리자` 메뉴 진입 (`/admin/boms`).
2. "새 BOM 초안 만들기" — 이름/차종 입력, 기존 활성 BOM 있으면 "원가 복사" 체크 여부 선택.
3. 만들어진 초안에 엑셀 업로드 (`bom_file`) → 신규/갱신 건수, 이전 입력 이관 건수 flash로 확인.
4. 초안 국가 설정 (한국은 항상 고정 포함 + 해외 국가 선택) 저장.
5. 필요 시 초안 행 수동 추가/수정 (`상세 BOM` 편집) — 품명 비우면 저장 거부됨.
6. 행이 1건 이상인지 확인 후 "확정(배포)" → `publish_draft`. 이 순간부터 사용자에게 노출됨.
7. 확정 후에는 해당 초안 재수정 불가 (status가 draft가 아니면 업로드/국가설정/행수정 전부 400).

**검증**: BOM 관리 화면에서 새 BOM 이름/Rev 표시되는지, 일반 사용자 계정으로 그리드에 행 보이는지 확인.

### 케이스 A-2. 기존 BOM 개정 (Rev 올리기)
1. "새 BOM 초안 만들기" 시 "원가 복사" 체크 → 기존 활성 BOM의 사용자 입력을 이관 대상으로 유지.
2. 개정 엑셀 업로드 (`replace_existing=True`로 초안 내용 전체 교체) → `migrate_matching_user_work`가 품번/품명 기준으로 이전 활성 BOM의 사용자 입력값을 자동 이관.
3. 국가 설정 재확인 (이전 설정 유지 안 될 수 있음 — 매번 다시 지정).
4. 확정 → 기존 활성 BOM은 자동으로 대체됨.

**검증**: 이관 건수 flash 메시지 확인. 사용자 쪽에서 이관된 값이 그대로 들어있는지, 신규 추가된 행은 미입력 상태인지 확인.

### 케이스 A-3. 배포 취소 (Withdraw)
1. 활성 BOM에서 "배포 취소" — 사유 입력.
2. 전체 사용자에게 공지(알림) 발송됨.
3. 취소 후 사용자 BOM 관리 화면은 "현재 사용할 수 있는 BOM이 없습니다" 빈 상태로 전환.

**검증**: 사유 없이도 취소 가능한지(현재 로직상 reason 없어도 통과 — 필요시 별도 확인), 사용자 알림 벨에 뜨는지.

### 케이스 A-4. 사용자 계정 생성
1. 사용자명/비밀번호/역할(admin 또는 user) 입력 후 생성.
2. 이미 존재하는 사용자명이면 "이미 존재하는 사용자명입니다" 표시 — 롤백 확인.

### 케이스 A-5. 제출 검토 - 승인
1. `제출 검토` 메뉴 (`/admin/reviews`) — 상태별(제출됨/승인/반려) 목록.
2. 특정 제출 상세 진입 → 스냅샷(제출 시점 값) + 리비전 히스토리 확인.
3. "승인" → 해당 사용자의 임시 입력(`bom_user_purchase_data`)이 정식 원가 데이터(`bom_purchase_data`)로 반영됨.
4. 승인 후에는 해당 사용자 그 BOM 재수정 불가 (상태 approved).

### 케이스 A-6. 제출 검토 - 반려
1. 반려 사유(`review_comment`) 입력 후 반려.
2. 사용자 쪽 상태 "반려"로 바뀌고 사유 노출 (`submission.review_comment`), 재수정 가능(status draft/returned 취급).
3. 사용자가 값 수정 후 재제출 → 다시 "제출됨" 상태로 검토 큐에 재등록.

**검증**: 반려→재수정→재제출 사이클 1회 끝까지 확인 (담당 품목 변경/취소도 반려 상태에서 다시 가능한지).

## User Work Flow

### 케이스 U-1. 담당 품목 지정 → 입력 → 제출 (정상 케이스)
1. `BOM 관리` 진입, 그리드에서 담당할 행 체크박스 선택.
2. "담당 품목 저장" 클릭 (저장 전까지는 해당 행 입력칸 잠겨 있음 — 정상 동작).
3. 저장 후 재료단가/물류단가/관세율/소싱 등 입력. 행 단위 자동/수동 저장 확인 (`row-autosave` dirty 처리).
4. 입력 진행률(`필수 재료단가 입력 X / Y`) 100% 확인.
5. "관리자 제출" → 확인 팝업 → 제출 완료.

### 케이스 U-2. 제출 실패 - 담당 품목 없음
1. 담당 품목 하나도 선택 안 한 채 "관리자 제출" 시도.
2. "먼저 본인이 입력할 담당 품목을 선택해 주세요." 422 에러 확인.

### 케이스 U-3. 제출 실패 - 미입력 항목 존재
1. 일부 담당 품목만 입력하고 제출 시도.
2. "필수 재료단가 입력이 N건 남아 있습니다." 확인.
3. "미입력만 보기" 필터로 누락 행 찾기 → 입력 → 재제출.

### 케이스 U-4. 담당 아닌 품목 편집 시도
1. 본인이 담당 지정 안 한 행의 입력칸을 강제로 활성화(혹은 다른 경로)해서 저장 시도.
2. "먼저 이 품목을 내 담당 품목으로 선택해 주세요." 메시지로 저장 거부되는지 확인.

### 케이스 U-5. 그룹 지정 / 해제
1. 상위-하위 관계인 품목들을 체크박스로 정확히 원하는 것만 선택 (2개 이상).
2. "선택 항목 그룹 지정/해제" 클릭.
3. 선택 항목 중 레벨(숫자)이 가장 낮은 품목이 자동으로 "상위"로 지정되는지 확인.
4. 그리드에서 상위 행 "그룹 상위 (N)" 배지 + 툴팁에 하위 품번/품명만 뜨는지 (상위 자기 자신은 목록에 안 뜸).
5. 하위 행에는 "그룹 하위 · 상위 {품번} · 담당 {담당자}" 배지 확인.
6. 하위 행은 재료단가 입력 잠김 (그룹 상위에서만 입력) 확인.
7. 같은 조합 다시 선택 후 "그룹 지정/해제" 클릭 → 그룹 해제되는지 확인.
8. **경계 케이스**: 선택 안 한 인접 행(형제/자식)이 자동으로 그룹에 딸려 들어가지 않는지 재확인 (과거 버그였던 부분).

### 케이스 U-6. 일괄 적용
1. 담당 품목으로 저장까지 끝난 행들을 체크.
2. 상단 "일괄 적용" 바에서 국가(국내/해외 전체/특정 국가) + 항목(재료단가/물류단가/관세율/금형비) + 값 선택.
3. "일괄 적용" 클릭 → 실제 반영된 행 수만큼 성공 메시지, "선택 저장"(임시 저장) 눌러야 서버에 반영됨.
4. **경계 케이스**: 담당 품목 저장 전 상태로 체크만 하고 일괄 적용 시도 → "적용할 수 있는 항목이 없습니다" 명확한 에러 뜨는지 (조용히 실패하면 버그).
5. **경계 케이스**: "국내" 선택 + 물류단가/관세율처럼 국내엔 없는 항목 선택 시도 → 동일하게 에러 처리되는지.

### 케이스 U-7. 내 담당 품목 페이지
1. 사이드바 "내 담당 품목" 진입 (`/bom/my-assignments`).
2. 현재 담당 지정한 품목 목록 확인.
3. 제출 전(작성 중/반려) 상태에서 "취소" 버튼으로 담당 해제 → 목록에서 즉시 사라지는지, 임시 저장 데이터가 남아 있어도 확실히 사라지는지.
4. 제출됨/승인 상태에서는 "취소" 버튼 대신 "제출됨" 표시로 바뀌고 취소 불가한지 확인.

### 케이스 U-8. 내 입력 전체 초기화
1. "내 입력 전체 초기화" 클릭 → 확인 팝업.
2. 담당 지정 + 입력값 전부 삭제되는지 확인 (`reset_user_bom_work`).
3. 제출된 상태에서도 초기화 가능한지 여부 확인 (막혀야 정상인지 정책 확인 필요 — 현재 라우트 상 제한 없어 보임, 실사용 시 재확인 권장).

### 케이스 U-9. 반려 후 재작업
케이스 A-6과 연계: 반려 사유 확인 → 해당 품목 재입력/담당 재조정 → 재제출까지 1 사이클.

### 케이스 U-10. BOM 배포 취소 상태에서 접근
1. 관리자가 배포 취소한 직후 그리드 접근 시 "현재 사용할 수 있는 BOM이 없습니다" 빈 상태 확인.

### 케이스 U-11. 내 제출 현황
1. 사이드바 "내 제출 현황" (`/bom/submissions`) — 과거 제출 이력/상태/리비전 히스토리 확인.

---

## 우선순위 제안 (그대로 따라 할 경우)
1. A-1 → U-1 (기본 골든 패스)
2. U-2, U-3, U-4 (에러 케이스)
3. U-5, U-6 (이번에 고친 그룹/일괄적용 회귀 확인)
4. A-6 → U-9 (반려 사이클)
5. U-7, U-8 (담당 품목 관리)
6. A-2, A-3 (개정/취소 - 데이터 이관 검증 필요해서 마지막)
