# PRD (Product Requirements Document) - TMS 부품 재료비 관리 포탈 (프로토타입)

문서버전: v1.0 (2026-08-13, 브레인스토밍 확정본) · 관련 문서: `BRD.md`

## 1. 개요

BOM 엑셀(`BOM 양식.xlsx`, NE2_NV1 차종)을 업로드하면 시스템화되고, 국가별(한국/미국/유럽) 소싱 원가를 포탈에서 입력·자동계산하며, 필요시 원본과 동일한 서식으로 다시 다운로드할 수 있는 로컬 웹앱 프로토타입.

## 2. 아키텍처

- Python **Streamlit** 로컬 웹앱 (`streamlit run app.py`, 브라우저 자동 오픈).
- **SQLite** 로 현재 데이터 저장.
- 원본 `BOM 양식.xlsx`는 (1) 최초/재업로드 파싱 소스 (2) 다운로드 시 서식 템플릿으로 사용. 원본 파일 자체는 직접 수정하지 않고 매번 사본에 값을 주입.
- 향후 다중사용자/권한분리 확장 시 FastAPI + React + 정식 DB 구조로 마이그레이션 예정 (본 PRD 범위 아님).

## 3. 데이터 모델 (SQLite)

| 테이블 | 주요 컬럼 | 비고 |
|---|---|---|
| `parts` | 품번(PK), 차종, 구분, LEVEL(0~6), 품명, 사양, 구성, 수량, 재질, 표면처리, 규격, 사이즈, 소재가격, 중량, 제품형상, 자작화검토, 비고 | 엑셀 B~AK열 매핑. 설계 업로드로 upsert됨 |
| `purchase_data` | 품번(FK), 소싱국가(한국/미국/유럽), 부품단가, 조립단가, CUR.(통화), 물류단가, 관세%, 재료비(계산값), 물류비(계산값), 관세(계산값), 총합계(계산값), 금형비, 포장/컨테이너 관련 항목 등 | 엑셀 AM열 이후 매핑. 포탈에서 직접 입력/계산 |
| `fx_rates` | 통화코드, 기준일자, 환율 | 외부 API로 1일 1회 갱신, 계산 시 해당일 고정값 사용 |

품번을 고유 식별자로 사용. 엑셀 원본의 셀 좌표(행/열)를 `parts`/`purchase_data`에 함께 저장해 다운로드 시 정확한 위치에 값을 되쓸 수 있도록 한다.

## 4. 기능 요구사항

### FR-1. BOM 업로드 (설계정보)
- 사용자가 BOM 엑셀 파일(B~AK열, 품번 포함)을 업로드.
- 시트/헤더 구조가 원본 템플릿과 다르면 업로드 거부하고 사유 표시.
- 품번 기준 upsert: 기존 품번이면 설계정보만 갱신(구매정보는 유지), 신규 품번이면 신규 행 추가.
- 파싱 실패 시 부분 반영 없이 전체 롤백.

### FR-2. 구매정보 입력 (웹 그리드)
- 품번별로 국가(한국/미국/유럽) 탭 또는 컬럼 구분해 부품단가·조립단가·통화·물류단가·관세율 등 입력.
- 입력값은 즉시 `purchase_data`에 저장.

### FR-3. 자동 계산
- 원본 엑셀 수식 로직을 재현: 재료비 = 단가 × 수량 × 환율(해당 통화, 해당일 고정값), 총합계 = 재료비 + 물류비 + 관세 등 원본과 동일한 산식.
- 계산에 필요한 값이 없으면(예: 환율 미확보) 결과는 공란으로 두고 사유 표시. 강제로 0 또는 임의값 채우지 않음.

### FR-4. 환율 관리
- 외부 무료 환율 API에서 1일 1회 자동 갱신, `fx_rates`에 기준일자와 함께 저장.
- 계산은 항상 "그 시점에 저장된 고정 환율"을 사용해 원가 재현성 확보(같은 날 재계산해도 같은 값).
- API 갱신 실패 시 전일자 값을 유지하고 화면에 경고 표시.

### FR-5. 엑셀 다운로드
- 원본 템플릿 사본을 열어 `parts` + `purchase_data` + 계산결과를 원래 셀 좌표에 그대로 주입.
- 원본의 서식(셀 병합, 열 구조, 다른 시트)은 변경하지 않음.
- 다운로드 파일명에 다운로드 일시 포함.

## 5. 비기능 요구사항

- 실행 환경: 로컬 PC(프로토타입 단계), 배포 환경은 추후 결정.
- 사용자: 1인(관리자) 동시 사용 기준, 동시성 제어 불필요.
- 데이터 정합성: 다운로드 파일은 반드시 원본과 동일한 서식 유지.
- 처리 규모: 부품 약 1,000행 기준으로 업로드/계산/다운로드가 수 초~수십 초 내 완료.

## 6. 에러 처리

| 상황 | 처리 |
|---|---|
| 업로드 파일 시트명/헤더 구조 상이 | 업로드 거부, 어떤 부분이 다른지 메시지로 안내 |
| 품번 중복/공백 행 | 해당 행 skip, skip된 품번 목록을 업로드 결과에 표시 |
| 환율 API 실패 | 전일 환율 유지, 화면에 "환율 갱신 실패, N일 전 값 사용중" 경고 |
| 계산 중 결측값/0나눔 | 결과 공란 처리, 원인 표시(예: "환율 미확보") |
| 다운로드 시 템플릿 파일 손상/부재 | 에러 메시지로 안내, 다운로드 중단 |

## 7. 화면 구성 (프로토타입)

1. **업로드 화면**: BOM 엑셀 업로드 버튼, 업로드 결과(신규/갱신/skip 건수) 표시.
2. **입력 그리드 화면**: 품번 목록(LEVEL 기준 들여쓰기 트리 표시), 국가별 구매정보 입력, 자동계산 결과 실시간 반영.
3. **환율 화면**: 현재 적용중인 환율/기준일자 조회, 필요시 수동 갱신 버튼.
4. **다운로드 화면**: 현재 데이터 기준 엑셀 다운로드 버튼.

## 8. 테스트/검증 계획

- 실제 BOM 파일(약 990행) 업로드 → 파싱된 부품 수가 원본과 일치하는지 확인.
- 원가 계산 결과 중 5~10건을 수기 계산과 대조.
- 설계정보 일부 수정 후 재업로드 → 기존 구매입력값(단가 등)이 그대로 유지되는지 확인.
- 다운로드한 엑셀을 열어 원본 대비 서식(병합/열구조) 깨짐이 없는지 육안 확인.

## 9. Out of Scope (본 프로토타입 제외)

- 로그인/사용자 인증, 관리자·설계자 권한 분리.
- 변경이력/감사로그(누가 언제 무엇을 바꿨는지).
- 재료비 SUMMARY(Sub total/Grand total), 개발단계별 버전관리/잠금.
- 목표가 관리, 약정인하/원자재 연동, BOM 자동매칭 등 로드맵 PHASE 2~5 기능.
- 다수 BOM/차종 동시 관리(현재는 NE2_NV1 1건).

이 항목들은 프로토타입 검증 후 로드맵에 따라 순차적으로 확장 논의.
