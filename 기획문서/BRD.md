# BRD (Business Requirements Document) - TMS 부품 재료비 관리 포탈

문서버전: v1.0 (2026-08-13, 브레인스토밍 확정본)

## 1. 배경

- 현재 재료비는 개인별로 로컬 엑셀 파일에 수기로 관리됨.
- 원가정보 취합 시 여러 담당자의 개별 엑셀을 수작업으로 모아야 해 시간이 걸리고, 버전 불일치/입력 오류 위험이 있음.
- 조직 내부적으로 재료비 관리 시스템 구축을 위한 5단계(PHASE) 로드맵이 이미 수립되어 있음 (상세는 `로드맵.md` 참고). 본 BRD/PRD가 다루는 범위는 이 로드맵의 PHASE 1을 검증하기 위한 프로토타입이다.

## 2. 목적

- BOM(Bill of Materials) 기반 재료비 정보를 웹 포탈에서 업로드/입력/조회/다운로드할 수 있는 시스템 구축.
- 엑셀 개별 관리 방식을 시스템 DB 기반 관리로 전환해 실시간 조회와 자동 집계가 가능하게 함.
- 향후 다중 사용자, 권한 분리, 개발단계별 버전관리, 약정인하/원자재 연동, 시점별 비교 분석(로드맵 PHASE 2~5)으로 단계적 확장.

## 3. 이해관계자

| 구분 | 역할 |
|---|---|
| 설계팀 | BOM 설계정보(품번/품명/사양/수량/재질/규격 등, 엑셀 B~AK열) 작성 및 제공 |
| 구매팀 | 포탈에 BOM 업로드, 국가별(한국/미국/유럽) 소싱단가·재료비·물류비·관세 등 입력(엑셀 AM열 이후) |
| 관리자(시스템 운영, 현 요청자) | 포탈 운영, 프로토타입 검증, 향후 확장 의사결정 |

## 4. 현황(As-Is) / 개선(To-Be)

| 구분 | As-Is | To-Be(프로토타입) |
|---|---|---|
| 데이터 위치 | 개인 PC 로컬 엑셀, 개별 관리 | 포탈 DB에 통합 저장 |
| 원가 취합 | 담당자별 파일 수합 필요 | 포탈에서 실시간 조회 |
| 원가 계산 | 엑셀 수식(일부 참조 깨짐 확인됨) | 포탈에서 자동 계산 |
| 출력물 | 원본 엑셀 그대로 사용 | 동일 서식의 엑셀로 다운로드 가능 |

## 5. 범위

### 본 프로토타입 범위 (In-Scope)
- 대상 BOM: `BOM 양식.xlsx` (NE2_NV1 차종) 1건.
- BOM 엑셀 업로드 → 설계정보(B~AK열) 파싱 → 품번 기준 시스템 반영(upsert).
- 포탈 화면에서 구매정보(AM열 이후: 국가별 단가 등) 입력.
- 단가 입력 시 재료비/총합계 등 자동 계산(원본 엑셀 수식 로직 재현).
- 환율은 외부에서 자동으로 가져와 반영(1일 1회 갱신 후 고정 사용).
- 원본과 동일한 서식(셀 배치/병합)을 유지한 엑셀 다운로드.
- 사용자: 관리자(요청자) 1인 검증 단계. 로그인/권한분리 없음.

### 향후 확장 범위 (Out-of-Scope, 로드맵 PHASE 1 정식판 이후)
- 다중 사용자 동시 입력, 관리자/설계자 권한 분리.
- 재료비 SUMMARY(품목군별 Sub total, 총재료비 Grand total).
- 개발단계(입찰/PROTO/PILOT/양산)별 재료비 확정·잠금·버전관리 (로드맵 PHASE 2).
- 목표가/재료비 인하항목 관리 (PHASE 3).
- 약정인하/원자재 연동, 변동이력 (PHASE 4).
- 시점/차종별 재료비 비교, BOM 자동매칭 (PHASE 5).
- 다수 BOM/차종 관리, 변경이력/감사로그.

## 6. 성공 기준

- 담당자(관리자)가 BOM을 업로드하면 시스템에 부품 목록이 자동 반영되는지 확인.
- 국가별 단가 입력 시 재료비/총합계가 원본 엑셀과 동일하게 자동 계산되는지 확인.
- 재업로드(설계정보 갱신) 시 기존에 입력한 구매정보(단가 등)가 유지되는지 확인.
- 다운로드한 엑셀이 원본과 동일한 서식(병합/셀배치)을 유지하는지 확인.

## 7. 제약사항 및 리스크

- 원본 BOM 엑셀의 재료비 계산 수식 일부가 `VLOOKUP(...,#REF!,...)` 형태로 깨져 있음(환율 참조 시트 소실). 포탈에서는 이 로직을 별도 환율 테이블로 재현.
- 배포 환경(로컬/사내서버/클라우드) 미정 - 프로토타입은 로컬 실행 기준으로 진행 후 결정.
- 로드맵 내 목표일정(PHASE1 ~2026-08-31 등)은 내부 목표일이며 확정 마감이 아님. 프로토타입 검증 후 순차 확장 방식으로 진행.
